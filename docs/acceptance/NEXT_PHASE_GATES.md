# 新阶段验收门槛与独立验证证据

- 版本：2026-10-13
- 目的：给 Work、代码评审者和未来 AI 自动化明确“完成”的含义；不是承诺当前项目已经完成这些检查。
- 状态枚举：`PASS`（真实通过）、`FAIL`（有失败证据）、`NOT RUN`（未执行）、`BLOCKED`（前提不满足）。不得只写“基本没问题”。

## 跨阶段硬门槛

1. **真实版本**：当前 PR/提交 SHA、对应 CI run、工具版本和数据库迁移可追溯；旧版通过不抵消新版失败。
2. **权限安全**：未授权、跨应用访问、停用账号和未经审批的高风险操作必须有服务端拒绝测试。
3. **数据可信**：市场发布状态、生命周期、运行健康、部署结果分开；外部数据含来源、最后采集时间与失败/未知状态。
4. **可恢复**：每个涉及写入外部系统或数据库变更的任务都有可执行恢复方案；容器回滚不等于数据库回滚。
5. **真实与模拟清晰**：不能将前端 Mock、合成指标、CI 实验环境或本机验证写成生产验收成功。
6. **人机安全**：AI 不授予自己权限；人批准具体动作/环境/版本/参数；暂停恢复不以过期状态继续提交，重复回调不得重复部署。
7. **最小必要基础设施**：没有独立证据的复杂组件暂不部署；拒绝一次性引入 Jenkins、GitLab Server、K8s、日志集群或多框架编排。

## AI 方向的提前验收口径（不得在 P5 之前打勾）

- `HITL-01`：AI 转人工时任务持久化，Worker 重启也能恢复等待；
- `HITL-02`：人工主动修改分支后，AI 续跑重新读取 Git SHA、CI 状态和策略；
- `HITL-03`：重复回调/网络超时/任务重放不会导致同一发布操作重复执行；
- `AUTO-01`：AI 编码仅可写入隔离环境，无生产密钥、无绕过分支保护；
- `AUTO-02`：低风险自动化由确定性策略放行，生产高风险动作需要授权或明确禁止；
- `OPS-01`：真实告警具备可复现的触发及恢复证据，数据失联显示 UNKNOWN/STALE；
- `OPS-02`：预定义操作的执行回执与最终状态分开，验证失败自动停止或按策略回退。

## 证据保存

每批 Work 将测试命令、返回码、GitHub run/PR、环境版本、SHA/digest、日志摘要、截图（如适用）及未覆盖场景写入对应 PR 描述或工程记录。公共仓库不得保存登录密码、Token、内部敏感日志和员工数据。
