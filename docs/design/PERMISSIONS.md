# 身份与授权矩阵（阶段 0 交付）

状态：首轮可执行方案；**产品已确认的部分**与**实施假设**分别标注。

## 1. 已确认的产品边界

- 仅已登录员工访问应用市场。
- 普通员工可使用市场，无默认应用创建权。
- 具备创建权限的员工可创建/提交应用，管理员审批才能对外发布。
- 所有正式上架应用对全体已登录员工可见；目标 Web 应用的使用权限由目标系统负责。
- 已发布信息更新重新审核、旧内容继续生效。
- 第一版采用独立用户系统，不用 SSO。

## 2. 最小权限模型

采用 **Better Auth Admin 插件的 `role=admin` 与 `banned` 账号状态 + `canCreateApp` 业务创建权 + 资源所有权**，不增加全功能 RBAC/ACL 表。单个管理员也可被授予创建权，但**审批操作要求管理员身份**。权限判断不是简单比较前端角色字符串。

| 动作 | 未登录 | 普通员工 | 有创建权限的员工 | 应用所有者（有创建权） | 管理员 |
| --- | --- | --- | --- | --- | --- |
| 登录 | 可尝试 | — | — | — | — |
| 查看上架列表和详情、打开外链 | 拒绝 | 允许 | 允许 | 允许 | 允许 |
| 查看自己创建的草稿、驳回结果 | 拒绝 | 仅自己已有资源* | 仅自己已有资源* | 允许 | 管理端只读可查 |
| 创建新应用 | 拒绝 | 拒绝 | 允许 | 允许 | 有创建权才允许 |
| 编辑属于自己的可编辑草稿 | 拒绝 | 拒绝* | 允许 | 允许 | 不默认代他人编辑 |
| 提交自己的草稿审核 | 拒绝 | 拒绝 | 允许 | 允许 | 有创建权才允许 |
| 查看待审核申请（全部） | 拒绝 | 拒绝 | 拒绝 | 只能看自己的 | 允许 |
| 审核通过或驳回 | 拒绝 | 拒绝 | 拒绝 | 无审核权则拒绝 | 允许** |
| 开通/停用账号、授予或撤回创建权 | 拒绝 | 拒绝 | 拒绝 | 拒绝 | 允许 |
| 下架已发布应用 | 拒绝 | 拒绝 | 拒绝 | 首轮尚不实现 | 后续阶段补充 |

\* **实施假设**：撤销创建权时仍允许查看自己已有申请记录，但不能新建、修改或再次提交；便于审计与反馈，不意味着保留发布权限。被停用的账号全部拒绝。

\*\* **实施假设**：管理员不能审批自己提交的申请，避免直接自批绕过复核。需两个不同用户完成演示，确认团队是否要在后续正式产品中保留此规则。

## 3. 身份生命周期（实施假设）

- **不开放自助注册**：管理员负责员工账号开通/停用；员工仅能登录或修改自己的密码。
- **首个管理员**：使用仓库的 `scripts/bootstrap-admin.mjs`，在 PostgreSQL advisory lock 下检查用户表为空，随后调用 Better Auth 的官方服务端 API 创建管理员并交互输入密码，不能将真实密码写在日志或 Shell 参数中。任何已有用户均拒绝再次运行。
- **普通员工开通**：管理员使用 Better Auth Admin 插件的受控接口开通员工；当前由管理员输入初始密码并通过安全渠道告知用户。首次登录强制改密与受控一次性重置已实现；见 [账号安全交付](../engineering/ACCOUNT_SECURITY.md)。
- **账号停用/撤权**：停用/恢复使用 Better Auth Admin 插件 ban/unban；服务端每次读取 live banned、role、canCreateApp；撤权后旧 session 无法继续越权操作。管理员禁用登录及旧 session 失效已在隔离数据库测试中验证。
- **密码重置**：首轮管理员发起受控重置（重置凭据一次性可用），不接入邮件服务；正式上线是否要求自助重置与邮件通知，在部署前重新评估。
- 保护最后一个有效管理员账户，避免系统不可管理：已通过 PostgreSQL 触发器实现并验证并发操作；后台隐藏按钮仅作为交互提示。

若 Better Auth 原生管理/重置接口不足以安全实现这些行为，第一轮须先做 Spike 评估，**不能绕过库直接更新密码哈希或弱化鉴权**。

## 4. 领域授权规则

建议维护下列中心化判定入口（命名示例，非强制 API）：

- `requireActiveSession`
- `requireCanCreateApp`
- `requireOwner(appId)`
- `requireAdmin`
- `requireReviewableSubmission(submissionId)`

所有创建、修改、提交、审核在服务器执行判定。服务端不可相信来自客户端的 ownerId、reviewerId、publishedRevisionId、状态字段；从 session 与数据库中取得并按事务更新。

**审批前**校验审核申请归属及 `PENDING` 状态；用原子状态转换消除重复审核。对并发通过/驳回只有一个成功，其他返回 409，不创建多余发布记录。

**公开读**仅允许 `LISTED AND published_revision_id IS NOT NULL` 的应用；查询详情、搜索、统计必须复用相同过滤逻辑。未公开应用不可通过猜测 id、客户端缓存或推荐 API 泄露。

## 5. 最小安全验收

1. 未登录请求 `/apps` 或对应 API 不返回应用资料。
2. 普通员工通过构造 HTTP 请求强行 POST 创建/提交应返回 403。
3. 创建者 A 通过替换 ID 修改创建者 B 的草稿应返回 403/404，数据不变。
4. 创建者有创建权限但无 admin 权限，仍无法审批。
5. 管理员（不是创建者）批准后，普通员工才能读到已发布版本。
6. 待审与驳回内容不会在公开接口、缓存、搜索/推荐中出现。
7. 管理员撤权后，原员工已登录会话下再次提交仍应被拒绝。
8. 账号停用后 session 不应继续访问管理或提交接口。

以上必须用**直接 HTTP/API 请求**及端到端操作双重验证，不以 UI 按钮是否隐藏作为证据。
