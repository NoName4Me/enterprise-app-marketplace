## 已编码待集中验证：P2-01

**目标**：让已登录员工在已上架应用详情中完成一条真实“使用申请 → 审批 → 处理结果”链路。代码已在 dev 提交；本批次按用户安排暂缓运行验证，不代表通过验收。

**先读**：现有 \`src/db/schema.ts\`、应用已发布读模型、Better Auth/当前 actor 权限、P1 owner 逻辑；避免复制第二套 Application 身份、引入通用 BPM 或绕过服务端权限。只修改必要的数据库迁移、领域逻辑、API、页面和少量文档。**Mac mini OrbStack 现有数据库/卷须保留；迁移先在隔离库验证**。

功能边界：
1. 应用公开详情提供申请入口。登录员工说明理由，提交后可看到自己的申请和状态；未接入目标 IAM 时，**不要显示已获应用权限**。
2. 默认按应用现有 owner 确定审批人；审批人和申请者相同或无合适责任人时转给经授权的管理员处理，仍**不能自己批准自己的申请**。无可用处理人不得偷偷批准，应显示需要人工配置/处理。
3. 有权限的审批人看到待办，批准或驳回并记录理由/操作人/时间；不同用户不能越权读取或修改请求，重复决策不能造成双重结果。
4. 审批通过与开通状态分离。首版允许授权维护人员将开通处理标记为**人工记录完成（未验证目标系统）**，并让申请者看到实际含义；没有接入目标 API 则不把状态写成“自动授权成功”。
5. 优先站内消息/状态反馈，邮件、IM、审批策略配置、自动权限分配、期限撤权和全面异常矩阵以后再做。

**最小验收**：实际用不同账号走通员工申请 → 有权审批 → 人工记录处理 → 员工看到结果；驳回分支可用；普通用户/本人自批被服务端拒绝；已上架公开信息不泄漏申请数据；迁移不清理现有数据库。普通 UI/CRUD **不要求新增全套单测/DB/E2E**，必要的权限、迁移检查仍需实测。测试未运行标记 NOT RUN，结果写 PR，不新建任务报告文档。

**阶段退出不要求**：通用流程引擎、多级审批/会签、全量通知渠道、目标应用 IAM 接入、全部边界组合测试。
