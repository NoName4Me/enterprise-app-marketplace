## 当前已具备的事实与限制

原 MVP 已实现账户与应用登记、审核/上架、员工浏览、版本复审、收藏、评价和讨论等基础能力；场景找应用只有关键词基线。Docker standalone 在部分历史 CI 已做过容器烟测，但**没有正式生产部署**。最新 `master` 的 [CI 运行 38386790784](https://github.com/NoName4Me/enterprise-app-marketplace/actions/runs/38386790784) 仍在 `Bootstrap initial administrator` 失败，导致后续测试没有全部执行；之前通过的报告不代表当前版本已经绿灯。

MVP-1 的详细历史设计/测试仍以 [PRD](PRD.md)、[MVP1 验收](acceptance/MVP1.md) 和 [工程交付记录](engineering/DELIVERY.md) 为准。本路线图定义**后续版本**，不倒写旧阶段已经满足新要求。

## 总体排序与阶段验收

| 优先 | 工作包 | 最小交付 / 退出条件 |
| --- | --- | --- |
| **P0** | **质量、安全与开发基线** | 独立数据库可重复通过管理员初始化、数据库/E2E/构建/容器 CI；必要检查成为有效合并门禁；不得通过删除安全防护“修绿” |
| **LAB** | **Mac mini 混合实验环境** | Apple Silicon 上门户 + 隔离数据库 + 一个测试服务可运行；GitHub Actions 构建 GHCR 镜像；Mac 按 digest 部署/回滚并留证据；初期手动发布可接受 |
| **P1** | **资产、生命周期、开发者工作台** | 一个真实测试应用关联组件、环境、负责人、仓库/流水线；生命周期独立于上架及部署状态；敏感资产信息有权限隔离 |
| **P2** | **申请审批与协作中心** | 员工申请应用使用、指定审批人、期限与撤销、通知和我的待办、审计；不得混淆门户批准和目标授权 |
| **P3** | **需求中心与真正的智能发现** | 提交/讨论/去重/认领/关联应用；AI 推荐以可评测的已上架数据为依据，错误和无匹配有可观测行为 |
| **P4** | **运维 L1 聚合** | 真实 CI/CD、目标容器部署、监控与告警在应用页可关联；状态含来源、时效及深度链接；监控缺失不虚报“正常” |
| **P5** | **共享长任务与人机接力** | 独立 Worker 的任务可持久化、中断、人工接管、恢复、重试、取消、审计；通过重复回调/重启等故障测试 |
| **P6** | **AI 需求交付** | 至少一个低风险 Bug 由 AI 在隔离分支修复、CI、人工接力、测试环境部署与结果验证；自动合并仅按可验证策略启用 |
| **P7** | **AI 诊断与受控运维 L2** | 一个预定义安全故障可被检测、解释、受控处理并验证恢复；高风险和状态未知转人工 |
| **P8** | **AI 从零建应用与增强自治** | 在 P6/P7 可靠性证据后，再决定自动创建仓库/应用与生产自治的开放范围 |

**依赖**：P0 是全部工作的最低准入；LAB 与 P1 可在稳定基线上分批推进；P2/P3/P4 可按资源交错；P5 可做独立 PoC，但 P6/P7 依赖其持久化与权限证据；P8 最后。L2 操作列表以后按频率/风险随用随增减。

## 首批执行顺序（Work 应逐任务交付，禁止一口气实现 P0–P8）

1. `P0-T01` 修复最新管理员初始化回归并重新跑全部 CI。
2. `P0-T02` 核对 GitHub 必需检查、PR 合并策略、Secrets/依赖安全基线；无法通过工具设置时列具体人工界面操作，不假装保护已生效。
3. `LAB-T01` 对 Mac mini 做资源、Docker/Node/磁盘检查并建立开发、测试、部署环境隔离；**只准备 PostgreSQL 和简单试验服务**。
4. `LAB-T02` 真实 GitHub Actions → GHCR → Mac mini ARM64 的构建、部署与回退试验。
5. `P1-T01` 审核当前数据模型与页面，提出最小资产/环境/组件/负责人方案及迁移、权限和验收；确认后再做代码。
6. 后续按 P2–P8 对应业务任务包逐次实施。

详见 [Work 工作指令](engineering/WORK_HANDOFF.md) 和 [分期验收门槛](acceptance/NEXT_PHASE_GATES.md)。

## 已讨论但暂缓的功能

原五大候选已融合：使用申请 → P2；需求广场 → P3/P6；AI 智能发现 → P3；开发者中心 → P1；**Agent/工作流市场暂停**。独立论坛低优先级。详细需求池在 [EXPANSION_BACKLOG.md](product/EXPANSION_BACKLOG.md)。

## AI Native 协作约定

Chat 负责关键产品和技术权衡；Work 负责需要实际修改仓库、配置外部系统、运行测试、采集证据的任务。每轮以小 PR 或明确单一任务提交、独立验证、回滚和交付记录收尾。既不要求人工手写大量代码，也不接受“AI 说测试通过”作为证据。
