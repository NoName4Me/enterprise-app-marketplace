# 产品：企业应用治理与 AI 自动化运维门户

企业内部非营利平台，不分析目标应用自身经营数据。业务从已有 Web 应用市场，逐步扩展至应用生命周期、使用申请、需求中心、智能应用发现、运维聚合和 AI 人机协作研发/运维。

## 已有业务不变量

- 员工独立登录；仅获得创建权限的员工可登记/更新应用；管理员审核，申请人不得自批。
- 市场只展示已批准且上架的快照；新版本待审期间旧批准版本继续有效，审核成功原子切换。市场登记版本与实际代码/部署版本独立。
- 登录员工可看到上架应用，不意味着已经得到目标系统实际访问权限；收藏、分类、搜索、评分、评价、应用讨论和管理员内容治理已实现。
- “场景找应用”现只有关键词基线，不是完整 LLM 方案；未来 AI 必须基于真实上架信息推荐，解释证据，不虚构应用。
- P1 资产/组件/环境/外部 GitHub 引用、负责人和生命周期属于私有维护数据，不混入公开市场。只登记引用不代表第三方已联通或部署健康，见 [ASSETS](ASSETS.md)。

## 原五类候选全部处理

| 方向 | 安排 |
| --- | --- |
| 应用使用权限申请 | **P2** 申请/审批/待办/通知，门户批准 ≠ 目标系统已授权 |
| 需求广场 | **P3** 提需求、合并/投票、认领、关联应用和交付；需求 ≠ AI 执行任务 |
| 真正的 AI 应用发现 | **P3** 可信自然语言发现、依据展示、质量评估 |
| 开发者中心 | **P1** 资产/生命周期/维护工作台，后续加发布和运维视图 |
| Agent/工作流市场 | **暂缓**（不影响内部开发和运维 AI Agent） |
| 独立论坛 | 低优先级；应用详情讨论区已存在 |

统一 Shell/搜索/通知 + 员工、维护者、审批人、运维、管理员工作台，同一人可有多个职责；服务端授权按资源/操作/环境决定。L1 运维聚合真实流水线、部署、健康、告警并深链专业系统，L2 简单高频受控操作以后按需增删，不自建 Git/Jenkins/K8s/完整监控。

AI 未来可从需求自动编码、测试、CI/CD、发布，或在故障时诊断和执行受控修复，支持转人工、人工接管后续跑。**无人工审核不等于无安全、版本和发布策略校验**；AI 不能自授权限。
