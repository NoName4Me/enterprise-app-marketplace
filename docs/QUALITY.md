# 快速开发阶段：测试与文档规则

目标是**先完成业务需求、跑通主流程，然后按阶段做深入测试**。现有测试代码保留，不删除服务端安全防护或数据库约束。

| 变更类型 | 当前默认要求 | 目前不强制 |
| --- | --- | --- |
| UI、搜索、普通 CRUD | 主流程实际可用，typecheck/lint/build | 新增自动化 unit/DB/E2E、复杂边缘矩阵 |
| 申请/审批业务状态 | 一条真实主链路、明显越权/非法状态拒绝 | 所有并发与异常组合 |
| 身份/私有资源 | 服务端访问拒绝及敏感数据隔离 | 全套浏览器角色排列 |
| 数据库迁移 | 隔离库迁移、现有数据安全和必要回退验证 | 无关页面的 DB 测试 |
| 部署/AI 自动写入 | 可信源 SHA、环境/权限、不可变摘要、失败/恢复基本验证 | 全面生产容灾与容量测试 |

普通功能**可不新增自动化测试**；已有测试留待 master 回归和阶段性补强。主流程没运行写 NOT RUN，失败写 FAIL，不能将 Mock/历史结果称 PASS。

PR 描述只需写明实现内容、如何操作主流程、实际执行验证和已知风险。**不再按任务新建 PLAN、DESIGN、ACCEPTANCE、STATUS、DELIVERY 等多份文档**。长期产品/架构/环境变更分别更新 [PRODUCT](PRODUCT.md)、[ARCHITECTURE](ARCHITECTURE.md)、[DEVELOPMENT](DEVELOPMENT.md) 或少量必要 ADR；一次性过程放 PR/CI/Git 历史。

P2–P4 功能基本齐备后集中补关键回归；P5–P8 的长任务、人工接力、AI 发布/修复在实际写外部系统前再强化幂等、错误、权限和中断恢复测试。PR 轻量 `validate` 不是发布门禁，实验 GHCR 发布仍验证 master 完整成功 CI。
