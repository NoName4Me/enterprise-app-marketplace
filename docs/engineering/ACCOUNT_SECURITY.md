# 账号安全增量交付

2026-10-13。范围为用户指定的剩余任务第 2 组：账号安全；AI、社区完善和正式部署暂停。

## 已实现

- 新开通的密码账号和初始化管理员默认必须改密。首次登录只允许查询会话、退出及修改密码，业务页面统一跳转 `/account/security`；业务 API 和领域授权独立拒绝未改密账号。客户端不能自行修改该标志或创建权限。
- 改密使用 Better Auth `changePassword`，验证当前密码，要求新密码 12–128 字符且不同于原密码；服务端强制撤销旧会话，认证库创建新的当前会话。
- 管理员在账号列表核实员工身份、填写原因后生成 15 分钟的一次性重置链接。自身账号使用正常改密流程；停用账号不能生成链接。生成链接立即撤销目标用户会话并删除旧重置令牌，新密码设置后无需再次改密。
- 一次性令牌的生成、过期检查和原子消费复用 Better Auth 的 `requestPasswordReset` / `resetPassword`。不接入邮件服务，不开放匿名申请重置；管理员通过企业认可的私密渠道交付链接。链接通过 URL fragment 交付令牌，令牌不会进入 HTTP URL 日志或 Referer；重置页面读取后去除地址栏令牌，并设置 no-referrer/no-index。
- 拦截未经控制的管理员直接设置密码及模拟他人登录入口。管理员恢复账号仍通过 Better Auth unban，最后管理员保护沿用已验证的 PostgreSQL 触发器。
- 安全事件记录登录成功/失败、退出、账号开通/停用/恢复、角色与创建权限调整、撤销会话、改密、重置链接签发与消费；敏感操作失败单独记录。仅记录操作人/目标 ID、时间、限定字段前后状态及重置原因，不记录密码、哈希、会话令牌、重置令牌、请求正文或邮箱。
- HTTP 认证写操作在 Drizzle 事务上下文中运行；认证库适配器、业务安全标志和审计共享同一连接。按用户 ID 顺序锁定账号，避免同一账号改密、登录与重置之间的竞态。审计失败时整个敏感操作回滚；会话与密码写入仍由认证库完成。
- 登录限速及认证端点限速显式开启，使用 PostgreSQL 原子 upsert 的 Better Auth customStorage，跨实例共享且不会随认证失败事务回滚；限速使用独立的小连接池，避免多个认证事务占满业务池后计数器无法获取连接。登录同一邮箱最多 10 次/5 分钟；来源的登录请求 20 次/分钟；改密和令牌消费 10 次/5 分钟；管理员签发重置链接 10 次/5 分钟。过期限速记录自动清理。
- 流式 JSON 请求读取限制 16 KiB，即使缺少 Content-Length 也会拒绝超限输入。

## 迁移与兼容

`0004_violet_whistler.sql` 添加 `must_change_password`、安全审计表及限速表。已有账号迁移为无需首次改密，新账号默认必须改密，避免中断当前开发会话。历史初始密码是否已经由员工修改无法从数据库推断，正式启用前应由管理员为仍使用初始凭据的旧账号签发重置链接。

测试夹具同样执行真正的首次改密；CI 初始化管理员后运行受限的 `prepare-test-admin.ts`。脚本只允许 CI 中 localhost 的 `market_test` 数据库，使用公开、明确的测试凭据，绝不改真实开发账号密码。

## 验证证据

- 隔离 PostgreSQL 数据库：4 个集成测试文件、17 项通过，包括既有授权/审核/版本隔离、最后管理员保护及新增账号安全闭环。测试数据库在结束后删除；现有开发数据未用于破坏性测试。
- 新增场景覆盖：未改密访问被拒；错误/相同密码不解除限制；改密后旧会话失效；管理员权限与同源限制；重发令牌使旧令牌失效；过期和并发重复消费被拒；重置后可正常登录；审计故障注入回滚密码；审计没有凭据；数据库限速并发原子性及登录 429。
- 7 项单元测试、lint、typecheck、生产 build 通过。
- 在用户已有 Chrome 会话检查 `/account/security`、账号管理入口和页面布局。没有修改当前真实登录账号的密码，也未重启用户的数据库或应用。
- 未在本轮执行 Chromium 全流程 E2E；已更新 CI 中旧夹具的首登改密步骤。正式 DNS/TLS、备份/恢复及生产部署不在本轮范围。

## 部署配置边界

限速默认不信任客户端自带的 IP 头，无法解析来源时采用按路径共享桶；邮箱桶仍独立生效。如设置 `AUTH_TRUSTED_IP_HEADER`，只能使用反向代理覆盖写入的头，且必须禁止客户端绕过代理直达应用。HTTPS、代理配置和部署实测属于后续第 4 组任务。

DB 超级用户可绕过触发器或修改审计记录；生产应用账号与迁移账号的权限隔离、审计保留/归档、企业身份核实流程仍需在正式部署时落实。这些部署条件不等于本轮代码功能未实现。

## 官方兼容性依据

基于锁定 Better Auth 1.7.6 的本地源代码和类型，结合官方 [Hooks](https://better-auth.com/docs/concepts/hooks)、[邮件密码](https://better-auth.com/docs/authentication/email-password)、[Admin 插件](https://better-auth.com/docs/plugins/admin)、[配置选项](https://better-auth.com/docs/reference/options)。未新增依赖，未自行实现密码哈希、令牌或会话签发。
