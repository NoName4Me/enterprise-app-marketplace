# P0-T01：管理员初始化修复

日期：2026-10-14。基线：master `7eb93f07ab2193fe52bfaff60d7bc5f2bd0c2876`。

## 根因与权衡

在新建 PostgreSQL 16 fixture 上，旧脚本真实返回退出码 1：`敏感字段必须使用专用管理入口`。锁定 `auth@1.7.6` CLI 的 create-admin 默认向 `data` 传入 `emailVerified: true`；应用 before hook 先拒绝该敏感字段。CLI 还会由配置重新实例化 Better Auth，因此不能可靠继承应用私有的进程内授权上下文。

改用 [Better Auth 官方服务端 createUser API](https://better-auth.com/docs/plugins/admin#create-user)，保持依赖锁定 1.7.6，不自行写密码哈希或会话。`bootstrapInitialAdministrator` 使用私有 AsyncLocalStorage 标记，且只接受邮箱、姓名、密码；角色和验证字段由服务端固定。HTTP 和普通 auth.api 无会话创建均被拒绝。受控入口不挂载路由，不使用环境开关/请求头授予权限。

外层 advisory lock 保留；创建事务内再锁 user 表并复查空库，阻止并发/直接调用绕过检查。账号、密码凭据、首登改密标记和审计在同一事务中。最后管理员数据库保护完全保留。

交互密码隐藏输入并确认，通过子进程 stdin 传递，不进入子进程参数或日志。`--ci-test-password` 仍只允许 CI=true、本机 market_test fixture。演示/安全测试改为显式本地合成数据入口，生产禁用，管理员 fixture 只允许隔离 CI 库。
