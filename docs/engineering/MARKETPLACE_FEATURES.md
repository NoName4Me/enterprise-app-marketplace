# 市场与互动功能增量

2026-10-13；用户授权继续推进产品需求，以关键节点可运行为验证目标，并授权在现有本地开发库加入明确标记的演示应用。

## 本轮任务范围

实现路线图阶段 2 的市场基础能力、阶段 3 的评价及应用讨论、阶段 4 的可运行匹配基线。不扩展应用类型、独立论坛、SSO 或目标应用运行平台。

### 实施口径

- 分类沿用办公、数据分析、研发工具、协作沟通、其他。
- 搜索同时匹配名称和简介；关键词按字面量处理，支持与分类、收藏过滤组合。
- 最新取当前公开版本的审核通过时间；热门按收藏用户数量排序；评分为未隐藏的有效评价平均值；推荐由管理员设置。
- 每个员工对应用最多一条有效评分/评价，更新使用数据库唯一约束和 upsert；评分必须是 1–5 的整数。
- 修改评价后清除对应的旧发布者回复，防止回复对应已被替换的内容。
- 发布者只能回复自己负责应用的评价；不能因此删除他人的评价。
- 管理员隐藏评价/讨论必须填写原因，并记录审计事件；隐藏评价不参与评分。作者可删除自身内容。
- 讨论仅支持主题和一层回复；删除或隐藏主题同时隐藏其回复。
- 下架/恢复仅由管理员操作并记录原因。恢复沿用之前审核通过的版本，取消人工推荐，不公开新草稿或待审版本。
- 新的 cookie 鉴权写接口验证同源 Origin，所有服务用例独立检查账号状态、权限、所有权与公开状态。
- 收藏/评价/讨论写操作锁定应用，与审批和上下架操作使用一致的应用行锁，确保状态一致。

## 数据和路由

迁移 `0002_powerful_skreet.sql` 新增收藏、评价、讨论和市场审计表，在应用上新增管理员推荐标记；不改变既有批准版本指针。

页面：`/apps`、`/favorites`、`/apps/[id]`、`/discover`、`/admin/catalog`。

写接口：`/api/apps/[id]/favorite`、`/feedback`、`/discussions`、`/community`；市场管理：`/api/admin/catalog/[id]`。读写接口均禁止公开缓存；私有管理页面检查管理员资格。

`pnpm demo:seed` 仅允许本地开发数据库。演示应用使用 example.com 外链，并明确说明不提供真实企业服务；通过领域服务完成草稿、提交和另一管理员审核。演示账号由 Better Auth 服务端 API 创建，未配置登录密码，不可用于邮箱密码登录。重复执行不会复制已有演示应用，也不会覆盖现有账号权限。

## 场景发现基线

对已上架版本的名称、简介、描述进行场景关键词匹配，给出实际文本命中依据。明确表达的排除场景不被推荐；无匹配时不生成虚构应用。当前最多扫描前 480 个已上架应用、返回 6 个候选。没有 LLM、向量检索或应用内答疑，不声明关键词匹配是 AI 推理。

## 验证与限制

- 实际执行迁移、lint、typecheck、单元测试和生产构建。
- 演示加载烟测真实验证：待审不可见、审核后可见、收藏重复写保持一条、评分修改保持一条、下架后列表/详情不可见及恢复。
- Chrome 使用用户已登录的 localhost:3000 实际验证：收藏并在收藏页显示、发布评分/文字评价、发布讨论成功、场景查找返回两条有依据的候选、管理列表与操作记录正常显示；不需要新建测试数据库。
- 单元测试 2 个文件共 5 项通过，包含既有权限用例以及场景匹配、无结果和明确排除需求；最后管理记录增量再次执行 lint、typecheck 和生产构建通过。
- 没有执行完整旧版三账号 E2E 或生产验收；更细的并发、分页边界与权限组合回归留待 CI/后续验收。
- 收藏统计不等于访问量；未实现浏览量榜单或真实 AI 服务。评价、讨论每次最多读 100 条，尚无长列表分页。
- 隐藏内容恢复、举报流程、首次登录改密、账号恢复、最后管理员保护和真实部署仍未完成。

## 运行

```sh
pnpm db:migrate
pnpm demo:seed
pnpm dev
```

已有应用服务可在迁移后直接刷新；演示载入不会重建已有开发数据库。
