## 代码防护

PR 标题检查改为 `pull_request_target`，严格 checkout PR **base.sha**，不 checkout、不构建、不执行 PR head 的代码。Token 只有 contents:read，不持久化到 checkout；标题只经环境变量传入，不插入 shell。脚本识别该事件，拒绝多行标题并转义日志输出。该可信触发器在本 PR 合并进入默认分支后才生效。

业务 CI 仍在 `pull_request` 的 GitHub 云端隔离 Runner 上执行；只含公开合成 fixture 凭据。Actions 锁定实际核对的 v4 完整 SHA，取消持久化 checkout 凭据，任务有超时。新增 npm/GitHub Actions Dependabot 每周扫描，不启用自动批准或自动合并。CI 新增官方 npm registry 生产依赖审计，高危/严重失败即返回非零。

## 依赖审计与兼容升级

初始 `pnpm audit --prod --registry=https://registry.npmjs.org` 发现 39 个公告：3 critical、18 high、15 moderate、3 low；主要为 Next.js/Sharp/PostCSS。默认本机 npmmirror 不实现 audit endpoint，已明确改用官方 registry，不把镜像报错当作通过。

按 [Next.js 官方升级说明](https://nextjs.org/docs/app/guides/upgrading/version-16) 与 [修复公告](https://github.com/advisories/GHSA-39w2-rjm5-chcv)，最小更新 Next.js/eslint-config-next 至锁定 16.3.8；保持 React 19.2 和 Better Auth 1.7.6。Node 22、React19、Playwright1.56 均符合该版本官方 peer/engine 范围。锁文件使用 Sharp0.35.5、PostCSS8.5.23。既有 @better-auth/utils peer 曾被解析为0.5.0，与官方1.7.6要求0.4.2不符，显式安装并锁定兼容 peer 0.4.2。

升级后高危/严重/低危归零；剩余 1 moderate：Drizzle Kit 的旧 @esbuild-kit 工具链 esbuild 开发服务跨源读取公告（https://github.com/advisories/GHSA-67mh-4wv8-2f99）。项目只用其构建API，不启动esbuild服务。保留真实审计结果，不以强制替换跨版本工具链掩盖风险。该项需后续兼容升级Drizzle工具链；审计阈值为high而非“零漏洞”验收。
