# 交付、回退与独立验收（阶段 0 交付）

状态：**Node/Docker standalone 容器已经通过 CI 独立 PostgreSQL 冒烟；生产环境尚未部署，也未做真实备份恢复演练**。

## 1. 环境与发布策略

| 环境 | 存储 | 用途 |
| --- | --- | --- |
| 本地开发 | Docker Compose PostgreSQL，开发专用数据卷 | 功能研发 |
| 自动化测试 | 单独 PostgreSQL 数据库/容器，每次清理 | 单元、集成和 E2E，不混用开发数据 |
| Preview/Staging（阶段 5 前确定） | 隔离 PostgreSQL、隔离密钥 | 部署演练和验收 |
| Production（首轮不部署） | 托管 PostgreSQL、独立密钥与备份 | 将来真实运行 |

首轮 **Node.js 应用 + PostgreSQL**，Docker 为可移植部署基线。生产必须有 HTTPS、日志收集、数据库备份、权限受限的环境密钥。不能将数据库放在临时/只读文件系统里。

## 2. 技术兼容性与部署 Spike

在真正决定使用 ChatGPT Sites 之前必须验证：

- [ ] 是否支持所选 Next.js 的 Node server 特性、持久 Session 和同源 API？

## 3. 发布操作手册（待首次部署实测补齐命令）

1. 在干净环境安装锁定依赖，执行 lint/typecheck/unit/integration/E2E/build。
2. 检查 `.env` 不存在于 Git，密钥通过部署平台机密变量注入。
3. 建立数据库备份与恢复点，核对迁移 SQL 对现有版本前向兼容。
4. 单独执行迁移，记录版本；如涉及破坏性变更则禁止直接无备份执行。
5. 发布不可变构建版本（Git SHA 对应产物），确认健康状态。
6. 使用测试租户/安全测试账号完成冒烟：登录 → 已上架目录；普通员工创建被拒；管理员可进入审核列表。
7. 记录部署 SHA、时间、迁移版本、测试结果和遇到的问题。

## 4. 回退策略

**应用代码缺陷**：
- 保留上一个可运行版本/镜像；部署失败或冒烟失败时切回前一制品。
- 新版本数据库迁移必须尽量向前兼容，确保旧代码可继续使用，否则发布前明确切换窗口和恢复方案。

**迁移或数据缺陷**：
- 代码回滚**不自动回滚数据库**。如果数据已经被新结构写入，应评估恢复、向前修复或补偿迁移。
- 破坏性迁移前需可验证备份；记录 RPO/RTO 目标，并在首次上线前演练恢复。
- 不依赖 `drizzle-kit push` 直接变更生产数据库。

**AI 编码质量缺陷**：
- 变更通过 PR；出现越权、泄露、流程不变量破坏时阻止合并。
- 合并后的回退优先通过 `git revert <commit>` / revert PR，保留证据；不同批次不要混合重构与业务变更。
- 重要设计变更写 ADR 并更新相应验收用例。

## 5. CI 必需检查（代码出现后设置）

- `install --frozen-lockfile`
- 格式、Lint、TypeScript strict、依赖/敏感信息扫描
- 单元 + PostgreSQL 集成 + Playwright 冒烟
- 构建
- PR 报告每项实际执行结果；任何未执行项标明 NOT RUN

当前 CI 已实际执行类型、Lint、数据库集成、Chromium E2E、构建和 Docker 容器烟测；生产部署、数据备份/恢复、云平台兼容性和完整账号安全仍未通过验收。详见 [T05 容器交付](T05_CONTAINER.md)。
